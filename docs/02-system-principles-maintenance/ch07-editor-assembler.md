# 第七章 6502 的编辑/汇编程序

## §7-1 汇编语言程序概述

### 一、汇编语言的特点

在第三章中我们已介绍了 6502 汇编语言的格式，所举的程序例中也已采用了这种格式。可以看到，汇编语言是一种直接与计算机指令系统密切相连的计算机语言。它直接用计算机指令的汇编符号来编写程序。除此以外，汇编语言还提供一些伪指令。这些伪指令在写程序中可以象指令一样地被使用。它们有的是对汇编过程（将汇编语言源程序转换成机器码表示的目的程序这一过程为汇编）本身进行控制或提供一定参数；有的是为程序的执行提供数据区或数据；还有的是对目的程序的属性，与其他程序的关系等等做出规定。使用汇编符号表示的指令和伪指令，按照一定的格式和语法关系写的程序，便是汇编语言源程序。用系统提供的软件汇编器（Assembler），或称汇编程序，便可将这种源程序汇编成目的程序。

因此，汇编语言与机器语言相比，明显地有下述优越性：

1. 用汇编符号代替数字，比较直观，容易记忆。
2. 用标号代替地址，写程序时不必经常地去计算地址值（这对程序分支转移等都提供很大方便），甚至完全可不考虑地址的绝对数值问题。
3. 程序修改比较方便，不会因修改一条而牵动整体。
4. 允许操作数为某些简单的表达式，也可含有标号，这给某些使用提供了很大的方便。
5. 对源程序进行注解，便于阅读、理解。

在有了伪指令以后，汇编语言又增加了其他优点。例如，这样一条伪指令语句：

```text
DATA DS 256; RESERVE A DATA AERA
```

即可从标号为 `DATA` 的内存单元开始，保留 256 个单元用做数据区。又如：

```text
STRN ASC APPLE2
```

这一语句可使之从标号为 `STRN` 的内存单元开始存储一个字符串 `"APPLE2"`（以 ASCII 码的形式存储）。

由此可见，有了伪指令对保留内存区，保留某些特殊字符等均很方便了。

以后还将看到，伪指令还有许多其他功能，这都使汇编语言程序的功能加强了。

另外，与计算机高级语言相比，虽然汇编语言仍是低级语言，使用不方便，比较繁琐，且与机器密切相关。但它却有下面的特点：

1. 节省内存空间和 CPU 资源。
2. 执行速度较快。
3. 能准确地掌握程序执行时间。

因此，在许多方面，尤其是实时的控制系统和数据采集系统中，经常使用汇编语言。有些软件和系统软件的开发，也离不开它。另外许多高级语言程序也常用汇编语言编写完成某些功能的子程序，然后调用它们。

计算机系统除了提供汇编器外，为了便于用户编写汇编语言源程序，也均提供一编辑程序（Editor）。利用这个程序，用户可以方便地输入、储存、修改、编辑、输出自己的汇编语言程序。

### 二、6502 编辑/汇编程序简介

#### （一）程序的运行

当前使用的 6502 编辑/汇编程序原是为 Apple II 设计的。这个程序在磁盘上共存有下述五个文件：

- `EDASM`（BASIC 语言程序）
- `EDASM.OBJ`（目的程序）
- `ASSM`（目的程序）
- `EDITOR`（目的程序）
- `ASMIDSTAMP`（二进制文件）

其中，中间的三个文件是主要的。`EDITOR` 是编辑程序；`ASSM` 是汇编程序；`EDASM.OBJ` 是编辑汇编的命令解释程序。6502 编辑/汇编程序主要由这三个部分构成。运行 `EDASM.OBJ` 程序时，将自动地把 `EDITOR` 引入内存中，然后进入命令方式。当输入汇编命令时，则又自动根据命令要求，引入 `ASSM` 程序，对磁盘中的某源程序文件进行汇编，产生目的程序文件。因此，运行编辑/汇编程序的 DOS 命令是：

```text
BRUN EDASM.OBJ
```

通常运行它时，若有两个软盘驱动器，应把盘片放在 #1 驱动器中。

也可以运行 BASIC 语言程序 `EDASM`，以进入编辑/汇编的命令方式。

使用命令：

```text
RUN EDASM
```

这时，屏幕上会出现：

```text
APPLE II EDITOR ASSEMBLER
CURRENT ASSEMBLER ID STAMP IS:
5 JUN 83 0000063
```

然后等待用户输入。如果用的盘是封写的，可打回车，便可自动运行 `EDASM.OBJ` 了。若未封写，最多可以输入 17 个字符（多于 17 个时，多的字符无效），然后打回车。这时系统将把这 17 个字符存入 `ASMIDSTAMP` 文件之中。下次再运行 `EDASM` 时，上述显示的第 3 行将出现该 17 个字符（若输入的字符数小于 17，仍将原来文件 `ASMIDSTAMP` 中后边的字符补上，凑齐 17 个）。

可见，最好的使用方法是直接调用 `EDASM.OBJ` 文件，可很快地进入编辑/汇编程序中。

编辑/汇编程序的提示符是冒号 `:`，光标为一下划线 `_`（或 `-`）。在这个方式下，除可使用编辑/汇编命令外，也可使用 DOS 的所有命令。不过使用时必须在 DOS 命令前加一点 `.`。例如，想连通打印机需使用命令：

```text
.PR#1
```

从这个命令方式退回到 BASIC 状态下，可使用命令 `"END"`；若要进入到监控状态，则要使用命令 `"MON"`。若从监控状态返回到编辑/汇编的命令方式下，则使用 `"3D0G"` 或 `"CTRL-RESET"` 即可（使用 `CTRL-C` 或 `CTRL-B` 则仍返回到 BASIC 状态）。

#### （二）命令一览表

在编辑/汇编程序的命令方式下，用户有 31 个命令可以使用。它们可分成三类：一是编辑命令。这部分命令主要可用来在内存中制作一个文本文件（以 ASCII 码形式存在的文件），通常这个文件是一个汇编语言源程序。事实上用户也可用来编写一个随意的文本。第二类命令是操作命令，主要是在编辑文本过程中提供一些辅助手段。例如，控制文本所存的内存区域，了解存放情形，了解磁盘中文件目录，访问磁盘或磁带机做文件的输入输出，等等。最后一类只有一个命令，就是汇编命令。它可对指定的、保存在磁盘上的源程序进行汇编。

除了上述的 31 个命令外，还有一个 `?` 命令。它给用户提供一个帮助，执行时，分两页在屏幕上显示出 31 个命令的名称及格式。我们把显示的结果列在表 7-1 中（显示时仅先显示表中前 17 行，按任何键后，再显示下一页）。

### 三、汇编过程说明

上面说过，6502 编辑/汇编程序是由三部分构成的，在命令方式下，汇编程序并没有调到内存中来，只有在使用 `"ASM"` 命令进行汇编时，它才取代编辑程序而进入内存。被汇编的源程序则要求一定要存在磁盘上。

汇编过程采取两次对源程序进行扫描的方法，即汇编器对源程序自头到尾“阅读”两次。第一次阅读后，主要是产生一个符号表，第二次才产生出整个目的程序。这种“阅读”是从磁盘中边调入边进行的。在第二次扫描中则同时把产生的目的程序按 256 个字节为一段，逐段地写到磁盘上的输出目的程序文件中去。在扫描过程中会把错误信息打出来（指出那些行是错的）。如果没有错误，机器最后给出 `"NO ERROR"` 的信息。

下面我们简单说明，为什么两次扫描可以从源程序产生出目的程序来。

汇编器中主要存放有两个表格。一个是机器操作码表 MOT（Machine Operation Table）；一个是伪指令操作表 POT（Pseudo Operation Table）。另外还有一个内存地址计数器 LC（Location Counter）。在第一次扫描过程中 LC 从 0 开始不停地追踪源程序行，对每一行均根据 MOT 和 POT 两个表求出其在目的程序中应占的单元数，根据此数修改 LC（不停地加算得的数）。当遇到有标号时，便把 LC 当时的值赋给它。因此在第一次扫描后，各标号的值便可确定下来了。这样，便可产生一个符号表，对所有的符号和标号均赋好了值。而第二次扫描时，再次逐条查找 MOT 和 POT 两个表，当遇到操作数中有标号时，便可从符号表中查出它的值代入。这样，便可最后形成目的程序。当然，与此同时，汇编器还要将汇编结果输出（包括存盘、显示），要检查和处理出错信息等等。

下边举一个简单的例子来说明。这里先给出一个将 16 个数据构成的数据块，从它存放的内存单元 `DATA`—`DATA+15` 中搬到 0 页的 `$F0`—`$FF` 单元中去的一段子程序的汇编语言源程序：

```text
 1        ORG $8000
 2 BUFFER EQU $F0
 3 START  LDX #0
 4        LDA DATA, X
 5        STA BUFFER, X
 6        INX
 7        CPX #16
 8        BNE START
 9        RTS
10 DATA   DS 16
```

我们先分析一下几个伪指令的作用。第 1 行中的 `"ORG $8000"` 即表示下面的程序是产生绝对目的地址的，其起始的内存单元地址为 `$8000`。第 2 行为一等值语句，即表示下面的源程序中符号 `BUFFER` 均将代之以 `$F0` 这个数。第 10 行则表示，这里开始保留 16 个单元（但暂不存放任何信息）。

现在看一下第一次扫描时会产生什么结果，开始 `LC=0`，但扫到第 1 行时，它便从 POT（原文印作 PRT）表中查到 `"ORG"` 伪指令的含意，就会自动将 LC 置为 `$8000`（`=32768`）。扫第 2 行时，又是一伪指令，它不影响 LC，而只在符号表中建立起第一个符号值 `"BUFFER=$F0"`。扫第 3 行时，由于有标号 `"START"`，而 `LC=$8000`，便将 `$8000` 这个值赋给了标号 `"START"`。这是符号表中的第 2 行。同时从 MOT 中得知 `"LDX #0"` 为两字节指令，LC 便自动加 2，变成 `$8002`。扫到第 4 行时，看到 `DATA` 是个前面没有赋值过的符号，汇编器便把它当做一个 16 位的地址值来计算，因而 `"LDA DATA, X"` 这条指令必为 3 字节者。这样 LC 又变成 `$8005`。而在扫到第 5 行时，由于 `"BUFFER"` 这个符号已定义为 `$F0`，可以知道它是 0 页地址了，因此可判断此行的指令为两字节者，LC 变成 `$8007`。以此类推，在最后一行时又得到 `"DATA"` 为 `$800D`。这样，在第一次扫描中便建立起了符号表，这段源程序中的所有标号和符号，均被赋予了具体的值。

在第二次扫描时便可根据 POT 和 MOT 这两个表和刚产生的符号表把所有源程序中的指令均汇编成机器语言的数码了。

从上面说明的过程中也可看到，在 6502 汇编源程序中，对于 0 页的标号或单字节符号（例如上面的 `"BUFFER"`）均应在引用它们之前定义。如果放在后面，例如上面的 `"BUFFER EQU $F0"` 放在第 5 行之后，则第 1 次扫描时将按 `"STA BUFFER, X"`（原文作 `"LDA BUFFER, X"`）这条指令是 3 字节的来处理。这种引用为“向前引用”（确定其值之前已引用）。对于非 0 页标号，显然向前引用是允许的。

## §7-2 汇编语言源程序

### 一、源程序的格式

源程序是由若干个逻辑记录组成的，每个记录均以回车符为结尾。我们也称一个记录为一行，或一个语句。当然编辑程序对它进行列表时，通常每行前均补上一个行号。行号是从 1 开始连续的正整数。

但是要汇编出目的程序来，每个逻辑记录必须满足下面的条件：

（1）满足汇编程序对它的格式要求。

（2）所使用的指令和伪指令必须是符合规定的。

第三章已介绍了 6502 指令系统。下面我们将介绍主要的汇编语言伪指令。

汇编程序规定，源程序的每个行可分成四个字段。即：标号字段、操作码字段、操作数字段和注释段。每一字段的具体格式和内容方面的规定如下：

1. **标号字段**：

   任何非纯注释语句均可有标号字段。标号必须用 `A` 到 `Z` 的英文大写字母之一开头，其中只准含有字母、数字和句号，不准含有空格。总计字符最多可为 16 个。

   标号必须是一行开头处开始，它必须是唯一的。即在一个源程序中一个标号只能定义一次。即使一个源程序包含有多个文件也得在各文件间遵守这一规定。

   有的特殊语句必须有标号，例如 `"EQU"` 伪指令为操作码字段的行就是如此。

   允许标号的最后字符为 `":"`，但它将不作为标号的一部分，只是列表时仍列在标号字段中。

2. **操作码字段**：

   必须是指令的汇编符号或者是伪指令的汇编符号。

3. **操作数字段**：

   操作数字段的有无取决于操作码字段是什么。有的操作码要求后跟操作数，有的则不要求。

   操作数字段是一个表达式，它可由常数、标号以及运算符 `+`、`-`、`*`（乘）、`/`（除）及 `<` 或 `>` 构成。所谓常数包括下述四种：

   （1）十进制常数：`0`—`65535` 之间

   （2）十六进制常数：`$0`—`$FFFF`（必须以字符 `"$"` 开头）

   （3）八进制常数：`@0`—`@177777`（必须以 `"@"` 开头）

   （4）串型常数：串型常数是一串字符，其两端要用单引号 `"'"` 括起来。汇编时，将取字符的 ASCII 码来作为它的数值。在不作特殊规定时，此 ASCII 码的最高位取为 1。例如 `'A'` 即汇编为 `$C1`（`A` 的 ASCII 码为 `$41`，中华学习机中通常存储的 ASCII 码高位为 1）。串型常数最长可达 240 个字符，但一个逻辑记录包括最后的回车符在内不得超过 256 个字符。因此，事实上允许串型常数为多少字符还要看它在行中的位置。由于 6502 的立即数是 8 位二进制数，不允许超过 `$FF`。所以串型常数作操作数字段时，仅其第一个字符是有效的。

   例如 `"LDA 'A'"` 这条指令经汇编后成为 `"A5 C1"`（注：`LDA #` 立即寻址机器码实为 `A9 C1`），即相当于 `"LDA $C1"`。而 `"LDA 'ABC'"` 这条指令同样也汇编出同一结果。又如 `"LDA 'A'+'B'"` 这条指令，将被汇编为 `"A5-83"`。即 `'A'+'B' = $C1 + $C2 = $83`（对 256 取模）。

   上面所说的运算符 `>` 和 `<` 是用来对一个常数或标号进行求低位数和高位数的操作。这里说的低位和高位数是按 4 位 16 进制数计算，低位数是其低两位数，高位数是其高两位数。例如在操作数中出现：

   ```text
   >$2080
   ```

   则将汇编成 `$80`。`">"` 后面若是一标号，也是一样处理。

   表达式中的运算符无优先级的规定，自左至右顺序运算。表达式计算结果不能超过 16 位二进制数所表达的范围，否则，汇编器将指出溢出错误。当表示一个 8 位立即数时，则结果按 256 取模。

4. **注释字段**：

   此为选用字段，汇编时对它是忽略的，只是在列源程序时将它们与上述字段一起列出。它可为任何一组 ASCII 字符。

   写程序时，除了四个字段要按上述规定写以外，还要注意整个行的格式，可综合以下几点规定：

   （1）各字段间通常以空格分开。

   （2）允许一行中仅有注释字段部分，此时为一纯注释语句，除纯注释语句外，其他语句均不得没有操作码字段。

   （3）空白语句是非法的（即不能在一行中没有任何字符，或有标号而无其他字段，等等）。

   （4）有些字段可以省略，但与其他字段间的空格一般不能省略（操作数字段例外，当它有明显的结束点时，后面的空格可以省略）。

   （5）纯注释语句可以 `"*"` 或 `";"` 开始。这样的语句汇编时将忽略，不产生目的程序。

   （6）一行最多只能包括 256 个字符。当输入字符超过 248 个时机器发出声响以提醒。

### 二、伪指令

共有 23 个伪指令。这里择其常用者分四类介绍于下。

#### （一）汇编控制伪指令

##### 1. ORG（置起始值）

格式：`"ORG 表达式"`

此语句用来建立目的代码的起始点，此语句允许有标号。汇编程序中若无此语句，则不产生目的程序文件，而只产生一个列表。因此 `ORG` 语句一般在源程序的开始。例如：

```text
START ORG $300
```

此语句表示以下的源程序建立的目的程序在内存的起点是地址为 `$300` 的单元。同时，标号 `START` 便也赋值为 `$300`。

一般情况下，一个源程序中只有一个这种语句，如果出现第二个，则从第二个该语句开始产生另一个目的程序文件。例如：

```text
ORG $300
...       }
...       } 第一个目的程序
...       }
ORG $2000
...       }
...       } 第二个目的程序
...       }
```

假定上面程序中仅有这两个 `ORG` 语句，则产生两个目的程序文件，但有 `DSECT` 伪指令时例外（见下面第 3 小段）。

此为 `ORG` 的绝对形式。还有一种相对形式，上述规定对它无效。其格式为：`"ORG * + |表达式|"` 或 `"ORG * - |表达式|"`。

例如，在源程序中出现 `"ORG * + 30"` 这一语句时，只将当前地址值（即汇编器的 LC）加 30。如在下例中：

```text
     ...
     ...
LOOP LDA #0
     STA DATA, X
     INX
     BNE LOOP
     RTS
     ORG * + $100
DATA DS 128
     ...
```

假定标号 `LOOP=$801`，则 `DATA` 这一语句原应为地址等于 `$80A`（假定 `DATA` 为非 0 页地址）。但遇到上面的 `ORG` 伪指令后，它变为 `$90A`。

##### 2. EQU（等值伪指令）

格式：`"标号 EQU 表达式"`

此语句用来给标号指定一个值。这个语句中应有标号，且不允许此标号再作其他语句的标号使用。例如：

```text
LOOP EQU $6E3A
     :
     LDA LOOP
     :
```

则 `LOOP` 赋值为 `$6E3A` 这个地址值，而 `"LDA LOOP"` 便被汇编为 `"LDA $6E3A"`。

##### 3. DSECT 和 DEND

格式：`"DSECT"` 和 `"DEND"`

这两条伪指令无操作数字段，它们配合使用。前面的命令表示以下语句只定义标号的值，而不产生目的程序。在它后面的 `"DEND"` 语句则表示这些语句的结束。当汇编器遇到 `"DSECT"` 时，保留当前的 LC 值，而把地址计数器 LC 置为 0。再遇到 `"DEND"` 语句时，地址计数器又恢复原来的值。在这段语句中，允许使用绝对形式的 `ORG` 语句，而不产生新的目的程序文件。例如：

```text
      ORG $8000
      :
      DSECT
      :
      ORG $F0
ADDX  DS  8
      :
      DEND
      :
```

在这段源程序中，`DSECT` 开始到 `DEND` 这当中的所有语句均不产生目的程序，因而，不允许有真正的指令操作码语句。假定在 `DSECT` 处 `LC = $8000 + L`（`L > 0`），而从 `DSECT`（原文印作 DESCT）开始 `LC = 0`，当遇到 `"ORG $F0"` 时，`LC = $F0`，因而 `ADDX` 这个标号赋值为 `$F0`。到 `DEND` 语句执行时，LC 又恢复为 `$8000 + L`，继续向下扫描。

`DSECT` 语句和 `DEND` 语句间不允许再出现此类语句，因而不允许嵌套。这两个语句经常用来定义数据项的标号值，而被定义的对象多在 0 页内（当然，不在 0 页也可以）。

##### 4. CHN（连续）

格式：`"CHN 源文件名 [, S#[, D#]]"`

这条伪指令表示当前的源程序后面要与另一源程序相连接。后者的源程序名要给出来，其所在磁盘驱动器的插槽号与驱动器分别为 `S#` 和 `D#`。但不指出这两个号码时，便说明此文件在当前的源程序所存在的磁盘中。由此可见，此语句一般是源程序的最后一行，例如：

```text
     ...
     ...
     ...
     STA $56FA
DONE RTS
     CHN TEST5
```

这个源程序在汇编时将会自动与 `TEST5` 这个汇编源程序一起汇编为一个目的程序。`TEST5` 这个程序接在现在这个程序的后面。

由于有这样一个语句，便于较大程序的开发。也可利用已开发的程序，以避免重复性工作，以提高效率。

##### 5. MSB（置最高位）

格式：`"MSB ON"` 或 `"MSB OFF"`

此命令是控制汇编产生的 ASCII 码的最高位置为 1 或 0 的。当有 `"MSB ON"` 命令时，后面的字符串所产生的 ASCII 码均为最高位等于 1。而 `"MSB OFF"` 则相反，产生的 ASCII 码的最高位等于 0。但这条命令对下面第（二）部分介绍的 `DCI` 伪指令不发生影响。当无此命令时，即相当于有 `"MSB ON"` 的情况。

#### （二）数据定义伪指令

##### 1. ASC（字符串定义）

格式：`"ASC 分界字符串"`

这里分界字符串为一串字符，但首尾为分界符。所谓分界符即非逗号（`,`）、连接号（`-`）、数字、空格和回车符的任一符号，但在该字符串本身不能再含有此符号。例如：

```text
'TIME AND SPACE'  （"'" 为分界符）
]ABCDEFG]         （"]" 为分界符）
HSYSTEMH          （"H" 为分界符）
```

在后面无注释字段时，仅用前面的分界符便可，后面的可省略。

这个命令用来在内存中存放该字符串的 ASCII 码。它们均为 8 位的，其高位取决于此语句前最接近的 `MSB` 语句（无此语句时，最高位为 1）。这些字符串码存放的起始单元，即为 LC 的当前值。此语句允许有标号，例如：

```text
BUFFER ASC '0123456789ABCDEF'
```

此语句使目的程序被引入时，从内存单元 `BUFFER` 开始有 16 个单元顺序存放 `0`—`F` 的 ASCII 码。`BUFFER` 的值象其他标号一样地被确定。

##### 2. DCI（字符串定义 2）

此命令格式全同于 `ASC`，只是汇编时不受 `MSB` 命令的控制。字符串的 ASCII 码中，前面的高位均为 0，最后一个高位为 1。

##### 3. DFB（字节定义）

格式：`"DFB 表达式 [, 表达式…]"`

相似于前面两个命令，但此时定义的不是字符的 ASCII 码，而是表达式所表示的数值。这些数的范围为 `0`—`255`，超过此值将按 256 取模。建议此命令中表达式数在 5—10 个这个范围中，最好不在一行中用过多的表达式，例如：

```text
DATA DFB 0, 1, 2, 3
     DFB 4, 5, 6, 7
     DFB 8, 9, $A, $B,
     DFB $C, $D, $E, $F
```

这就将在内存中从 `DATA` 这个单元开始有 16 个单元顺序存放 `0`—`$F` 这 16 个数。

##### 4. DW（字定义）

格式：`"DW 表达式"`

此命令定义一个“6502 字”。所谓“6502 字”即为一 16 位二进制数，其低 8 位存于第一单元，高 8 位则存第二单元。例如：

```text
WORD DW $03FE
```

这将在 `WORD` 单元存入 `$FE`，而 `WORD+1` 单元存放 `$03`。`WORD` 为标号，将赋予汇编时的 LC 值。

##### 5. DDB（双字节定义）

此命令与 `DW` 格式全同，差别在于产生的 16 位数高位存在前一单元，低位存后一单元。例如：

```text
WORD DDB $FE03
```

这一语句与上面的语句（`DW`）完全等效了。

##### 6. DS（保留存储单元命令）

格式：`"DS 表达式"`

这个语句的效果是从当前地址单元保存内存某些字节，保存数即为表达式的值，也允许有标号。这个命令多用来保留数据区。

#### （三）条件汇编伪指令

条件汇编命令共有三个，它们必须配合使用。

##### 1. DO（条件汇编命令）

格式：`"DO 表达式"`

这个命令起两个作用：1. 标志从此开始为条件汇编语句块；2. 根据表达式是否非 0 来决定条件汇编语言块（`FIN`）是否要进行汇编。

##### 2. FIN（条件汇编结束命令）

格式：`"FIN"`

从 `DO` 语句开始，遇到 `FIN` 前的语句均为条件汇编语句块的语句，它们是否汇编由 `DO` 语句的表达式决定。

##### 3. ELSE（汇编条件取反命令）

这个命令只能存在于条件汇编语句块之中。例如：

```text
DO 表达式
:  } 块 A
ELSE
:  } 块 B
FIN
```

此时把条件汇编语句块分成两个部分，我们称它们为块 A 和 B。当 `DO` 语句表达式值为 0 时，块 A 不进行汇编，但块 B 则要进行汇编；反之，若表达式非 0，则块 A 汇编而块 B 不汇编。

#### （四）列表伪指令

列表命令是用来对汇编时的输出列表格式进行控制，对目的程序无影响，共有六种：

##### 1. PAGE（换页）

格式：`"PAGE"`

遇到源程序中有此命令时，送给输出设备一信息，使其换页，同时送到显示屏上一个空行。它不产生任何目的程序。

##### 2. LST（列表）

格式：`"LST ON"` 或 `"LST OFF"`

遇到 `"LST OFF"` 时，在汇编的第二次扫描中对下面的行不输出列表。而遇到 `"LST ON"` 时则相反。源程序中无任何列表命令时，列表将自动地进行。利用列表命令可以对不想列表的部分加以控制以不出现在列表中。这可加速汇编的进行过程（尤其是有打印输出时）。

##### 3. SKP（跳行）

格式：`"SKP 表达式"`

汇编列表输出时遇到此命令，列表设备将列出一些空行，空行数等于表达式的值（以 256 取模）。

##### 4. SBTL（付标题）

格式：`"SBTL 分界字符串"`

此命令使汇编输出列表时每一页给出一个标题，标题的内容便是命令中提供的字符串。同时每页第一行还给出 ID 标记，然后打出页数。在打符号表时也给出标题 `"SYMBOL TABLE SORTED BY SYMBOL"` 和 `"SYMBOL TABAL SORTED BY ADDRESS"`。

##### 5. REP（重复字符串）

格式：`"REP 表达式"`

汇编时遇到这一语句，便输出一个重复的字符行。所重复的字符在不规定时为 `"*"`，也可用下面的命令（`CHR`）来规定。字符重复个数等于表达式的值（以 256 取模）。这提供一个分割子程序或程序模块的表示方法。

##### 6. CHR（重复字符）

格式：`"CHR? 字符"`

此命令要与上面的命令连用，用来规定命令 `REP` 引起的重复字符串中为什么字符。例如：

```text
   ...
   ...
15 CHR? #
16 REP 12
17 CHR? $
   ...
   ...
30 REP 15
```

假设 18 至 29 之间再无别的 `CHR` 语句，则输出列表时第 16 和 30 行分别如下：

```text
   ...
16 ############
   ...
   ...
30 $$$$$$$$$$$$$$$
   ...
   ...
```

`CHR` 语句中必须有问号，否则将按重复字符为空格来处理，事实上打印出一个空行。

## §7-3 汇编命令和汇编过程的控制

### 一、汇编命令

前面已简单介绍过汇编命令（`ASM`），它的格式是：

```text
ASM 源文件名, <目的文件名>, S<#>, D<#>
```

这个命令中指出了下述内容：被汇编的汇编语言源程序的文件名。产生的目的程序的文件名，以及存放目的程序的磁盘所在的驱动器的插槽号和驱动器号（`S` 和 `D`）。显然，这里面好象缺少了存源文件的磁盘所在的驱动器的插槽号和驱动器号。对此规定：存源文件的磁盘必须插在调用 `ASM` 命令时编辑程序所指向的磁盘驱动器中。

在执行 `ASM` 命令时，系统首先要调入汇编器。然后给出信息：

```text
PRESS ANY KEY TO COUNTINUE
```

此时，必须将有该源文件的盘插入到上述编辑程序所指向的磁盘驱动器中。如果该驱动器正好是存放编辑/汇编程序者，而盘上又无该源文件，则要取下该盘，换上有源文件的盘，然后再按一下任何键以开始汇编。当汇编结束时，自动又出现上述信息。此时可再将盘片换回，按任意键便再次将编辑程序引入内存，回到 `:` 提示符下。在汇编过程中，汇编器将自动地将目的程序存放到对应于命令中 `S#` 和 `D#` 的盘上去。如果目的程序也存放在源文件所在的盘上，上述的 `S#` 和 `D#` 是可省略的。对于中华学习机来说，插槽号已固定为 `#6`，因而不再考虑这一项。如果使用的是单驱动器系统（有的中华学习机可接两个软盘驱动器），对 `D` 这一项，事实上也无选择的余地。

目的程序文件名是可省略的。当省略时，系统自动命名它为 `"源文件名.OBJ0"`。如果汇编结果产生多个目的程序，则它们的文件名将依次为 `"源文件名.OBJ0"`、`"源文件名.OBJ1"`、……等等。

例如，系统在 #6 插槽上有两个磁盘驱动器 D1 和 D2。编辑/汇编程序是在 D1 上，而当前编辑程序指向驱动器 D2。若打入命令：

```text
ASM CNTS, CT1, D1
```

则系统会对 D2 上的源文件 `CNTS` 进行汇编。产生的目的程序名为 `CT1`，存于 D1 的磁盘中，如果在第一次出现 `"PRESS ANY KEY TO COUNTINUE"` 时，不换盘片，则目的程序将存在编辑/汇编程序所在的盘片上。又如：

```text
ASM TEST
```

此命令是要将源文件 `TEST`（存于当前指向的磁盘上）汇编成目的程序文件 `TEST.OBJ0`（假设只产生一个目的程序文件），仍存放在源文件所在的磁盘上。

### 二、汇编过程的控制

汇编过程是自动进行的。如果人不介入的话，将自动进行到结束。但在汇编过程中，有三种键盘命令可对汇编过程产生影响。

#### 1. CTRL-C

在汇编过程中，只要有此命令从键盘上输入，汇编工作将停止。此时系统将关闭所有打开的文件，释放正在使用的磁盘操作系统缓冲器。但如果已形成目的程序的输出文件的话，并不清除它。然后系统再进入命令方式。

#### 2. 空格键

在汇编的第二次扫描过程中，按一下空格键可使列表工作停止。然后如果再按任意其它键时，又继续下去，如果继续按空格键，则每按一次，列出一行。这可使列表工作“步进式”地进行。

#### 3. CTRL-N 和 CTRL-O

在汇编过程中若想停止列表，则可打入 `CTRL-N` 键。反之，若想从不列表状态进入列表状态，则可打入 `CTRL-O` 命令。这两个命令与源程序中的 `"LST OFF"` 和 `"LST ON"`（原文印作 `"LIST OFF"` 和 `"LIST ON"`）的作用相同，因此，有时键盘输入的 `CTRL-N` 或 `CTRL-O` 命令可能与源程序中的相应命令相抵消。此时若列表状态不是所希望状态时，可再从键盘上打入相应的命令。这两个命令一般是在大程序中才使用。当只想看一下部分列表时，便可用上述命令控制。

## §7-4 源程序的编辑

本节简单介绍如何在编辑/汇编的命令方式下建立和修改一个汇编语言源程序。在表 7-1 中列出了 31 个命令，其中 `ASM`，`END` 和 `MON` 均已说明过了。这里介绍其它 28 个命令的使用方法。

### 一、编辑命令

共有 10 个编辑命令，可以在命令方式下直接使用。它们是真正用来对汇编源程序进行编辑用的：

#### （一）INSERT（插入）

格式：`"INSERT 行号"`

这里的行号要求为 `1`—`65519` 的十进制整数。此命令表示从源程序的某一行开始插入。例如：

```text
I 1
```

这就可从第一行开始建立你的源程序了。接到此命令后，将显示行号 `1`，便可从这里开始输入你的程序。每遇到回车，增加一行，列出新的行号。如内存中已有了部分源程序，插入后原来的行顺序后移。又如：

```text
I 100
```

这一般是在内存中已经建立了部分源程序，要求从第 100 行开始插入一些行，插入后，原 100 行及其以后的行，均按插入的行数自动后移。

从插入方式下退出的方法是打入键 `CTRL-D` 或 `CTRL-Q`，再按一下回车。例如在上例中，若想插入 10 行（100—109），则当显示到行号 `110` 时，应退出。退出后，系统自动又进入命令方式。

#### （二）ADD（增加）

格式：`"ADD <行号>"`（`"< >"` 部分可以没有）

此命令用来对内存源文件增加一些行。如果命令不带行号，则从最后加起，如果有行号，则从给行号的后一行加起，因而 `"A8"` 命令与 `"I9"` 命令是完全等效的。如果在内存中没有任何源文件时，使用命令 `"A"`，系统便进入从第 1 行开始建立源文件的状态。退出该状态的方法也和插入方式的退出全同。

#### （三）CHANGE（更换）

格式：`"CHANGE <行号1<-行号2>>.字符串1.字符串2"`

这里的字符串 1 和 2 之间及字符串 1 开始处，均应有分界符。但字符串 2 后面可以有分界符，也可以没有而直接接回车符。这个命令的含意是从行号等于行号 1 的行开始到行号等于行号 2 的行中寻找字符串 1，把它们都改成字符串 2，如果命令中无行号，则内存中源程序所有行均进行上述更换。如果仅有行号 1，则仅对该行做上述更换。如果没有行号 2，但行号 1 后有连接符 `"-"`，则大不相同。它表示从该行起到最后一行均进行上述的更换。例如：

```text
C100.INC.DEX.
```

这个命令要求将 100 行中的字符串 `"INC"` 改成为 `"DEX"`。又如：

```text
C100-.X.Y
```

这个命令要求将 100 行以及其后的所有行中的 `X` 均变为 `Y`。系统执行此命令时，先用下述字符来提问：

```text
ALL OR SOME? (A/S)
```
（注：原文印作 `ALL OR SAME? (A/S)`）

如果你想一次更换好，打入除 `S` 和 `s` 以上的字符（如 `T`、`W` 等等）以外的任何字符，可以使系统自动完成命令要求的更换，更换的行被显示出来，然后回到命令方式。如果你按下 `S` 键，则进入逐条更换的方式。此时，系统每顺序找到一条应更换行，便显示在屏幕上，如果你要换它，可按下空格键（或另外的非控制键、非回车键）；如果不想更换该行，则可按下回车键（或 `ESC` 键，或任何非 `CTRL-C` 的其它控制键）。

如果在上述过程中，希望取消更换命令，可按 `CTRL-C` 键来达到此目的。

在字符串 1 中可以使用 `"CTRL-A"` 字符，它在这里的含意是“任一字符”（不包括回车）。例如：

```text
C95-.LOOP(CTRL-A).WAIT. （CTRL-A 不显示）
```

这一命令是将 95 行及其以后行中的所有字符串 `"LOOP*"` 均换成 `"WAIT"`。这里 `*` 是任意字符。

#### （四）COPY（复制）

格式：`"COPY 行号1-<行号2> TO 行号3"`

其中行号及连接号等的规定同前。这个命令要求将行号为行号 1 的行到行号为行号 2 的行这个范围中的所有源程序复制到从行号 3 开始的行中去。

此命令执行后被复制部分仍存在源程序中。但如果行号 3 小于行号 1 或 2 时，这部分程序要后移。例如：

```text
CO 4-8 TO 2
```

此命令执行后，新的源程序中 2—6 行的内容将为原来 4—8 行的内容，但 9—13 行也是这个内容。

#### （五）DELETE（删去）

格式：`"DELETE 行号1<-行号2>, ……"`

此命令为删除源程序中的某些行。允许有多个行的范围，但不允许前面的行号加连接号，而无后面的行号。例如：

```text
D25, 10-20, 3-5
```

这个命令将删除内存源程序的第 3—5，10—20 和第 25 共 15 行。但是命令 `"D3-"` 是不允许的，而 `"D3"` 是允许的。另外，在删除过程中，每删一段，后面的行号便又顺序向前提，因此，下面的命令：

```text
D 2-4, 8-10
```

执行结果将删去 2—4 和 11—13 行。因为删去 2—4 行后，原来的 11—13 行变成了 8—10 行。

#### （六）LIST（列表）

格式：`"LIST <行号1<-行号2>>, ……"`

此命令要求在显示屏幕上列表。若没有行号，则将内存中的源程序的所有行列出。若有行号范围，则只列出指出的范围，对行号的规定同于 `DELETE` 命令（但可以使用 `"行号1-"` 的形式）。

列表过程中可用 `CTRL-C` 来中止，回到命令方式；也可用空格键暂停，然后用 `CTRL-C` 以外的键恢复。如果连续按空格键，则为逐行列表的方式。

如果你想连续使用相同的列表命令，可以用 `CTRL-R` 来代替上次用过的列表命令。

#### （七）PRINT（不带行号的列表）

此命令与 `LIST` 全同，仅显示时不显示行号。

#### （八）REPLACE（置换）

格式：`"REPLACE <行号1<-行号2>>"`

这个命令事实上等效于 `DELETE` 命令和 `INSERT` 命令的相加。例如：

```text
R 100-105
```

这个命令执行结果等于下面两个命令执行的结果：

```text
D 100-105
I 100
```

#### （九）FIND（查找）

格式：`"FIND <行号1<-行号2>>, ……[字符串]"`

这个命令中有关行号的规定与 `LIST` 命令中的规定相同。字符串前面必需有分界符。

这个命令是要求在指出的行的范围中查找命令中给出的字符串，被找到者列表在显示屏上。字符串中允许使用 `"CTRL-A"` 来代表“任一字符”。

#### （十）EDIT（编辑）

格式：`"EDIT <行号1<-行号2>>, ……[字符串]"`

有关行号和字符串的规定仍同前，这个命令是功能最多的。它表示编程序者要求对指出的行的范围中，有该字符串的行进行编辑。接到此命令后系统将进入到逐行编辑方式。例如：

```text
E 1-
```

将使之进入从第一行开始的编辑，逐行列出源程序行。然后可对其进行修改。而命令：

```text
E 1
```

则列出第一行，编辑后马上返回命令方式。下面的命令：

```text
E 1-5, 10-20 .LDA
```

则使系统把 1—5 和 10—20 这些行中含有字符串 `"LDA"` 的行逐行地列出以进行编辑。

当进入逐行编辑方式时，便可进行插入、修改和删除字符等等操作。首先你可使用箭头键进行光标的移动，要在哪里进行上述操作，就让光标停在哪里。操作的方法如下：

1. 想插入一个或几个字符就先打 `CTRL-I`，然后打插入的字符，这些字符便会插在光标指向字符的前面。想结束插入则可用箭头键或除了 `CTRL-V` 以外的任何控制键。
2. 想删除一个字符，便可打 `CTRL-D`，光标指向的字符便删掉了。
3. 更换一个字母只需简单地打入欲换上的新字符便可。

如果想插入、更换的字符是控制字符，则操作更复杂些。若想插入一控制字符，则打入 `CTRL-I` 之后打入每个控制字符之前还需打一个 `CTRL-V`。如果你想用控制字符取代普通字符，则也要打 `CTRL-V`，然后打想换入的控制字符。至于删除，操作与普通字符相同。但是控制字符平常是不显示出来的，而在编辑方式下，当光标正好移在控制字符所在的位置时，控制字符会以闪烁方式出现。当光标移走时，控制字符也就消失了。例如：在屏幕上显示的为 `"……ABC……"` 时，光标指向 `B`。此时若打入 `CTRL-I`、`CTRL-V` 和 `CTRL-P` 时，事实上此行变为 `"……ACTRL-PBC……"`。但 `CTRL-P` 不显示出来，只有光标移至它应在的位置时（即从右边左移时，刚移过 `B`；或从左向右移时，刚移过 `A`），出现这种情形 `"……APBC……"`。此时，`CTRL-P` 以闪烁方式显示出来，同时 `BC` 等字符右移一格。在这个时候打入 `CTRL-D` 后，`CTRL-P` 便删除了。

在逐行编辑方式下还提供下述两手段，以便于编辑的进行：

##### 1. CTRL-F（查找）

当打入此控制字符再打另一欲查找的字符后，系统便从目前的光标处向右查找，找到第一个该字符时，将光标停在那里。若找不到，仍停在原处。

例如，在下述情形下打入 `CTRL-FG`：

```text
182 LOOP LDA DATA, X; A GET A DATA （光标在 L 处）
```

这时，光标便会移到注解中的 `G` 字符上：

```text
182 LOOP LDA DATA, X; A GET A DATA
```

但是如果打入的是 `CTRL-FY`，则光标仍不动，因为这一行中没有字符 `Y`。

##### 2. CTRL-R（恢复）

在对一行进行修改时，企图取消前面已进行了的所有修改而恢复修改前的行，则在打入回车之前，打入 `CTRL-R` 这个字符便可。这个时候，便可以重新对该行进行编辑了。例如原先的行是：

```text
182 LOOP LDA DATA, X; A GET A DATA
```

在修改过程中改成了下面的情形，光标停在 `X` 处：

```text
182 LOOP STY DATA, X; A GET A DATA
```

此时若打入 `CTRL-R`，便会恢复原先的行，而光标停在第一个字符上，进入重新编辑该行的状态。

对一行编辑完，欲进行下面的编辑时，可用两种方法：

1. **回车**

   不管光标停在何处，打入回车键后，该行便编辑结束，当时屏幕上的显示结果便取代了原先的行（包括不显示出来的控制字符）。

2. **CTRL-T**

   当打入此控制字符时，光标前的字符有效，光标处及其以后（右边）的字符均取消了。这个缩短了的行作为最后结果放进源程序中去。

由上述两种方法完成一行的编辑后，要么进入对下一个应编辑行进行编辑的方式，要么回到命令方式，视原输入的编辑命令的规定而定。如果希望整个退出编辑方式进入命令方式而不管原编辑命令的规定如何，可以使用 `"CTRL-X"`。在任何地方打入 `"CTRL-X"` 便立即回到命令方式。

### 二、操作命令

系统还提供以下一些操作类命令：

#### （一）LOAD（装入）

格式：`"LOAD 源文件名"`

此命令可使系统由指向的磁盘中读入指定的源程序文件。

#### （二）SAVE（保存）

格式：`"SAVE <行号1<-行号2>> [源文件名]"`

此命令要求将行号 1 到行号 2 范围内的行保存到指向的磁盘上，并命名为指出的文件名。如果无行号，则内存中整个源程序均保存。如果在执行此命令前已执行过 `"LOAD"` 或 `"SAVE"` 命令，则文件名可省，系统将自动命名它为上次访问过的文件名，即先删除盘上的该文件名的旧文件，而将内存中的内容取代它。

#### （三）APPEND（增补）

格式：`"APPEND <行号> 源文件名"`

此命令是将所指向磁盘中的该文件读入，而从指出的行号开始，接到内存已有的源程序中去。内存中原该行以后的行不被后移，而是被取代。

#### （四）SLOT（指向的磁盘插槽）

格式：`"SLOT 插槽号"`

此命令设置当前指向的磁盘插槽号。插槽号当然只是 1 到 7。对中华学习机来说，可忽略此命令。

#### （五）DRIVE（指向的磁盘驱动器）

格式：`"DRIVE 驱动器号"`

与上一命令相似，这一命令规定选择该插槽中两驱动器的哪一个。

#### （六）CATALOG（目录）

格式：`"CATALOG"`

接到这个命令，将把当前指向的磁盘驱动器上的文件目录显示出来。

#### （七）FILE（文件名存储）

格式：`"FILE"`

这个命令将使系统显示出最新访问过的文件名、它所在的磁盘驱动槽号、驱动器号、文件长度（字节数）及内存余下的字节数等。

#### （八）HIMEM（地址上界）

格式：`"HIMEM=地址值"`

地址值要是十进制数。此命令指出内存源程序文件可使用的最大地址。

如果不使用此命令，系统自动把上界定在 `38400`（相当于 `$9600`，原文作 `$95FF`），这是最大允许值。因此，一般不必使用此命令。

#### （九）LOMEM（地址下界）

格式：`"LOMEM=地址值"`

与上一命令相对应。通常系统自动置为 `8192`（相当于 `$2000`）。

#### （十）LENGTH

格式：`"LENGTH"`

接到此命令将显示出目前源程序文件所用的内存长度及余下的存储空间。

#### （十一）TRUNC（截短）

格式：`"TRUNC ON"` 或 `"TRUNC OFF"`

打入第一个命令后，由 `LIST` 或 `PRINT` 命令引起的列表将把源程序截短，而不显示注释字段。若打入第二个命令，则又恢复到不截短的状态。

#### （十二）WHERE（查找地址）

格式：`"WHERE 行号"`

机器将显示出内存中存放该行源程序的第一个单元的地址值。

#### （十三）PR#（打印）

格式：`"PR#插槽号, [设备控制字符串]"`

这个命令是使系统和其他外设相连。通常是与打印机相连，而打印出汇编的内容和符号表。例如，通常插槽号为 1，设备控制字符串可用来对 80 行打印机进行控制，使之初始化。字符串的前半部分是逻辑页长度和物理页长度。前者为 `"LX"`，`X` 为两位十进制数，它表示打印时一页所打印的行数；后者为 `"PY"`，`Y` 也是两位十进制数，它表示一页中自顶到底被分成的行数，若不给出逻辑页长度，则说明它是 60。而如果没给出物理页长度，当使用 `SBTL` 时，每页之后自动走纸。设备控制字符串的第二部分是必须要有的。对中华学习机来说所使用的 80 行打印机接口板要求这部分为 `"CTRL-I80N"`。这表示一行允许最多打 80 个字符。

例如打入命令：

```text
PR#1, L54P66CTRL-I80N/（CTRL-I 不显示）
```

当用 `ASM` 命令进行汇编时，打印机将逐段地随汇编过程打出汇编内容。打印时规定每页为 66 行而只打印 54 行，每行最多打 80 个字符。

#### （十四）TABS（规格化）

格式：`"TABS 数1<, 数2><, 数3>…[字符]"`

这个命令是用来对列表命令（`LIST` 和 `PRINT`）引起的列表格式进行控制的。如果不使用此命令，系统置在 6502 汇编语言标准格式下。此时列表格式如下：

| 行号 | 空格 | 标号字段 | 空格 | 操作码字段 | 空格 | 操作数字段 | 空格 | 注释字段 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 0—4 | 5 | 6—13 | 14 | 15—18 | 19 | 20—28 | 29 | 30 |

这个表中列出的数字是显示行中的字符列数。它们按空格来进行格式化。

若不想使用此格式，便可使用 `TABS` 这个格式化命令。但由于汇编程序规定空格为固定的格式化标记，因此命令中很少用到字符。即，一般仅为 $n$ 个递增的数字（`数1, 数2, …`）。这些数字均要为 `0`—`39` 之间才有效。最多可有 16 个。

例如 `T14, 19, 29`

此即为上述 6502 汇编语言标准格式相当的命令。即列表时第一个空格固定在 14 列，第二个在 19 列，第三个在 29 列（行号与标号间的空格是固有的，不能规定）。如使用命令：

```text
T14.D（字符前要有分界符）
```

则列表时在 14 列以前遇到有 `D` 字符时，便把 `D` 列在第 14 列，然后向右排下去。

#### （十五）NEW（刷新）

格式：`"NEW"`

此命令事实上并不将内存源文件清洗掉，而仅仅将内存源文件的结束点置为 `LOMEM` 命令指定的值（如无此命令，则为 `$2000`）。此时再用列命令时，将什么也不列出来。但是，如果在这种情形下想恢复内存源文件，可以将上述结束点置回原来的值。这个结束点存在 0 页 `$0E` 和 `$0F` 单元中。`$0E` 放其低位，`$0F` 放高位。如果将系统转到监控状态，恢复此二单元原先的值，然后再回到编辑/汇编的命令方式下时，再用列表命令可发现源程序得到恢复。上述两个单元称为源程序结束点地址指引元。

顺便说一下，在内存中的源程序文件是从 `LOMEM` 规定的地址（不规定则为 `$2000`，但不能比此值再低）开始安装的。中华学习机有 48K RAM 可用，可用来安装内存源程序的空间有 29.5K 字节（`$2000`—`$95FF`）。如果平均约 40 个字符组成一个逻辑记录，共可编制 700 多行的源程序文件。

#### （十六）TLOAD 和 TSAVE（盒式磁带读写操作）

格式：`"TLOAD 行号"` 和 `"TSAVE <行号1<-行号2>>"`

这是两个读写磁带命令，前者将使磁带中的源文件从指出的行号开始插入；后者则将内存源程序按指出的行范围写入磁带中。后者允许有多个行号范围。

由于没有磁盘子系统就无法运行编辑/汇编程序，因此这两个命令使用机会较少。

### 三、命令方式下的其他操作

在命令方式下还可以进行除上述各编辑/汇编命令外的其他操作。主要有以下几种：

#### （一）操作系统命令的使用

在命令方式下可以使用某些操作系统命令。但使用时要在命令前打入一个句号做首字符，这在前面已经讲过。例如：

```text
.RENAME 文件名1, 文件名2
```

此即可将磁盘上的文件中名字为 `文件名1` 的改为 `文件名2`。即相当执行了操作系统的 `RENAME` 命令。

#### （二）多个命令的输入

多个命令可以在一行中输入，而命令之间用命令分界符来分隔。分界符在没作特别规定时为冒号 `":"`。例如命令：

```text
D5-8: C5-8. X. Y.: L
```

这表示先删除第 5—8 行，然后把 5—8 行中的 `X` 变为 `Y`，再把所有源程序列出来。这里要注意，执行 `"C5-8. X. Y."` 时，事实上是更改了原来的 9—12 行。因为执行了 `D5-8` 后，原先的 9—12 行成为 5—8 行了。

另外，要用这种方式调用 `ASM` 命令时，`ASM` 命令必须为最后一个命令。

至于命令分界符，如果不想使用冒号，可用下法：在命令方式下按一下 `"ESC"` 键，然后按冒号，再按你想用的符号便可。但如果按的是空格键，则系统会发出嘟嘟声而等待输入另一字符。如果按下回车键，则会显示出当前的命令分界符。

命令分界符除了不能用空格和回车符外，也不能用句号。

#### （三）打印源程序

常常需要在程序调试和编写过程中把源程序打印出来检查，这可以使用操作系统命令 `".PR#1"` 先把打印机连通，然后用 `"LIST"` 或 `"PRINT"` 命令将需要的内容打印出来。但有时需要打印列数大于 40 列，而简单地使用上述命令只能每行打印 40 列。为此，可使用下述方法：打印机加电后，用 `"MON"` 命令进入监控，然后用监控命令将 `679`（十进制 `1655`，原文作 `1657`）单元置为希望得到的列数。例如，希望每行为 80 列，则可用命令：

```text
679: 50
```

之后，可以用 `"1CTRL-P 0 CTRL-K"` 把打印机连通，再用 `"3D0G"` 命令返回到编辑程序。也可以先回到编辑程序下，然后用 `".PR#1"` 操作系统命令把打印机连通。

断开打印机可直接用 `".PR#0"` 命令。

## §7-5 小结

综上所述，中华学习机的编辑/汇编程序是一个很好的汇编语言程序开发工具。我们可以使用它在机器上编写源程序，然后以文件形式存于软盘之中。虽然在内存中只能编写约 29.5K 字节的源程序，但由于有连接功能，可以把程序编得比这长得多，因而也可用它来开发较大型的程序。汇编程序可以对磁盘上的源程序进行汇编，产生出可以调入内存执行的目的程序。在汇编过程中还可打印出汇编结果及符号表等。

下面我们给出一个简单的例子，以说明制作汇编语言程序的全过程。我们仍以第三章的 §3-3 四中的气泡排序程序为例。要使该程序完整，需加入以下几个语句：

1. `ORG` 语句，我们假定该子程序将引到 `$8000` 开始的内存中去（若用 BASIC 语言调用，可用命令 `"CALL 32768"`），因此使用语句 `"ORG $8000"`。
2. 标号 `LENTH`、`LIST`、`SIGN` 和 `TEMP` 需用 `"EQU"` 语句分别进行定义。我们定义它们分别为 0 页地址 `$FD`、`$FE`、`$FC` 和 `$FA`。

这样，便可以在 DOS 下，运行编辑/汇编程序，把整个程序输入内存中，然后用 `"SAVE"` 命令将它以文件名 `"ORDER"` 存于磁盘中。这样就制作出了一个源程序文件。

继续在编辑命令方式下，使用下述两个命令可对文件 `ORDER` 进行汇编，并在打印机上以每行 80 列打印出汇编结果：

```text
PR#1CTRL-I80N
ASM ORDER ORDER.OBJ
```

后面列出了打印结果。它共有两部分：汇编程序列表和交叉符号表。在第一部分中列出了下述内容：

1. 源程序文件名（`SOURCE FILE`）
2. 目的程序文件名（`OBJECT FILE NAME`），它出现在 `ORG` 语句之前。
3. 逐行的汇编结果：从左到右，每行源程序语句均列出目的程序中该指令的存储地址、汇编得到的机器码（以 16 进制数表示）、行号及源程序语句本身。
4. 错误提示：若有错误，在错行前给出英文提示信息，并在最后指出本程序有错；若没有错误，最后给出信息：`"* * * SUCCESSFUL ASSEMBLY: NO ERRORS"`。

符号表中给出两个表，一个是按标号的字母顺序排列的；一个是按其地址值大小排列的。表中左边为该标号的地址，右边是标号本身。如果有的标号没有被引用，则在对应行前打印出一个 `"?"`。

产生的目的程序可用操作系统命令 `"BLOAD"` 引入内存中，如不规定内存地址，便按源程序中 `"ORG"` 语句的规定放置。也可直接用 `"BRUN"` 命令调用。
